## Result and deadline semantics

`POST /api/convert` formerly ran unbounded document work in a thread. It now
executes page counting, PDF parsing, reconciliation, XLSX/CSV writing, preview
base64 encoding and JSON serialization in a fresh disposable process. The
**default wall deadline is 30 seconds**, starting after a validated upload and
covering process startup, request/result IPC, all document work and child exit.
Timeout returns HTTP **504** with fixed safe retry/split guidance, localized in
all five UI locales. It does not expose file names, rows, exceptions or paths.

The deadline actively sends SIGKILL to the worker process group and waits for
reaping before releasing capacity. It also handles partial IPC, complete output
followed by a stuck exit, malformed/oversized frames, worker crashes, cancellation
and a full stdout pipe. Cleanup drains remaining pipe bytes in bounded chunks;
it does not leave a blocked parser or an accumulating zombie behind.

Two API admissions per ASGI process are held through conversion, parent billing,
response assembly and upload close. Excess requests fail promptly with HTTP 503;
there is no queued collection of PDFs or completed outputs behind a blocked
billing database. A separate two-child cap protects direct supervisor calls.
Host-wide child capacity is **ASGI worker count × 2**, not a global host limit.

Linux children have a **512 MiB address-space limit**, a CPU backstop of
`ceil(deadline) + 1` seconds, `RLIMIT_CORE=0` and `PR_SET_DUMPABLE=0`. The latter
also prevents Linux piped core collectors from dumping statement memory. These
guards are applied before PDF bytes are read by the child. Framed metadata is
limited to 4 KiB and encoded response bodies to **64 MiB** before billing.

`STX_CONVERSION_TIMEOUT_SECONDS` optionally selects a finite value greater than
zero and at most 120 seconds. Invalid, zero, negative, infinite or NaN settings
fail closed. The default needs no production configuration change. Upload
transport/multipart parsing and the existing bounded SQLite commit are outside
the document deadline; accepted upload size remains **20 MiB**, the multipart
memory threshold **21 MiB**, and the page cap **100**.

## Cleanup, privacy and billing

The child imports engine/writers, not API, billing, a ledger or a payment
provider. PDF, transaction, worksheet XML and output bytes cross memory pipes;
there are no conversion temporary files. Child stderr and ordinary library
stdout are discarded, while the dedicated binary protocol carries the result.
Unexpected errors return a fixed safe message. Uploads close in shielded cleanup
on success, rejection, timeout and cancellation; forced disk-spool regressions
verify immediate deletion before return.

Only a completely prepared artifact and successful child exit allow the parent
to commit usage. No transaction serialization or preview encoding remains after
the debit. Timeouts, resource failures, worker crashes and cancellation during
document work create no account/debit/retry metadata. Retrying the same file and
idempotency key after timeout succeeds and subsequent replay debits once. If a
request disconnects after completed work enters the existing billing commit,
cleanup waits for that parent thread, retains admission and uses the existing
idempotent lost-response retry behavior. Billing/provider/pricing decisions and
unmetered mode are unchanged. Existing expiry cleanup still follows its prior
24-hour contract.
