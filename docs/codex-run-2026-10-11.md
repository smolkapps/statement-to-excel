All four other locales carry faithful translations; `feature_private_*` is unchanged. Upload spill files close immediately on success and failure. In configured mode, account/credit and payment records persist. Conversion idempotency rows store a SHA-256 fingerprint with `created_at` and a 24-hour window, measured from creation without extension on replay. Every conversion POST purges expired rows, including rejected requests; with no conversion traffic, cleanup waits for the next request. Expired keys behave as new conversions and can consume usage again. The safe SQLite migration discards legacy fingerprints with unknown creation times while preserving balances and recorded usage. `AGENTS.md` and README state these retention rules plainly. Checkout and Pro entitlement idempotency remain unchanged. The existing Umami tag receives exactly `file-selected`, `convert-success`, `convert-error`, `upgrade-click`, `checkout-opened`, without document or account payloads. 5. **Unresolved issues.**

- The July production fallthrough is not currently reproducible: a safe synthetic production POST returned HTTP 200 JSON, five expected rows and one metered page. Production health still reports mock billing. These branch changes have not been deployed.
- Actual backend host, process manager, durable database mount, TLS/proxy configuration and external autodeploy settings remain unknown. The repository expects a separately supervised FastAPI service on port 8000 and same-origin `/api/*` forwarding before SPA fallback. The nginx example needs operator installation. Billing requires one durable SQLite database shared by workers on one host; multiple hosts need shared transactional storage.
- Real Stripe test-account credentials and deployed webhook delivery were unavailable. Tests exercise the real SDK/signature verification with synthetic transports; no actual payment was attempted.
- Password-protected PDFs require an unlocked copy; scanned transaction pages require OCR. Mixed scanned/text statements are rejected to prevent missing rows. Multi-page text statements pass; detected multi-account statements must be split. Account detection requires recognizable headers, and image-bearing pages without readable transactions are conservatively rejected, including some covers. Real-bank compatibility beyond the synthetic corpus remains unmeasured.
